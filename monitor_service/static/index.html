Журнал веб-приложения

Сервис читает новые строки из файла другого приложения: считает запросы, среднее время обработки и долю серверных ошибок.

Для учебного примера указано 10 мс обработки внутри приложения и отсутствие серверных ошибок. Для другого приложения задайте его требования. Это отдельная настройка от времени ожидания ответа клиентом. Настройки закрепляются за новым наблюдением; прежние модели не перенастраиваются.

Новое наблюдение создаёт отдельную модель и читает с текущего конца файла. Приложение уже должно непрерывно записывать запросы в этот файл. Новый точный формат: v2 ts=1792490400.123 status=200 rt=0.000285. Прежний v1 читается отдельно.

Сообщения журнала

«Тревога» — нарушение заданных требований к ответам. «Предупреждение» — необычные показатели модели, причина ещё не установлена. Восстановление качества подтверждается десятью последовательными секундами нормальных ответов. Предупреждение не считается заведомо ложным.

Учебное приложение

Небольшое отдельное приложение получает запросы. Здесь можно сопоставить его работу с уведомлениями модели.

Приложение ещё не запущено. Первоначальное обучение занимает около 15 минут.

Новый запуск приложения автоматически создаст журнал запросов. Его можно подключить в блоке «Журнал веб-приложения».

Модель показателей приложения не получает время ответа и коды ошибок. Для журнала создаётся другая модель: она получает показатели запросов за секунду. Команды включения проверок не входят в признаки ни одной модели.

Обычный поток — около двух запросов в секунду.

Лишние вычисления меняют работу внутри приложения, увеличение потока — число запросов. Эти проверки выполняются отдельно. Число запросов можно менять во время начального обучения; лишние вычисления доступны только после него.
