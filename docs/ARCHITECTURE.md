# Как устроен сервис

Программа запускает небольшой HTTP-сервер на этом компьютере. Браузер
получает от него страницу и периодически запрашивает новые данные.

1. Источник присылает числовые наблюдения через API либо дописывает access-лог.
2. `store.py` проверяет состав показателей, время и допустимость значений.
   Для журналов перед этим работают парсер, агрегатор и механизм чтения файла.
3. Детектор накапливает обычные наблюдения для начального обучения, затем
   рассчитывает оценку отклонения и сравнивает её с порогом.
4. Проверка наблюдений и обновление модели разделены. Для режима приложения
   проверяется каждая строка, обновления выполняются порциями.
5. Для журналов используются проверки пригодности обучения и качества ответов.
   Подозрительные наблюдения не должны автоматически становиться новой нормой.
6. Наблюдения, решения и состояние сохраняются в SQLite. Интерфейс показывает
   историю и различает начальную настройку, предупреждение, тревогу и восстановление.

`test_app.py` — именно учебное веб-приложение, а не набор unit-тестов.
`bench.py` управляет этим дочерним процессом и запросами к нему.
Имена некоторых модулей с `candidate` сохранены из разработки: эти модули
используются текущей версией и не являются отдельными запускаемыми программами.

## Разделение с исследованием

IPCA реализован через NumPy/SVD в `_reference_models.py`. Это применение
известного метода в процедуре мониторинга, а не заявка на новый алгоритм PCA.
При подготовке портфолио алгоритм детектора не подбирался заново.
